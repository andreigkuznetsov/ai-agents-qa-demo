# AI Agents QA Demo

Портфолио-стенд для тестирования AI-агента на сценариях создания обращения о переносе доставки. В целевой системе Logistics Agent работает с симулятором логистического API, QA Engine проверяет наблюдаемые события и состояние данных, а QA Agent оценивает обоснованность ответа.

Пользователь принял КТ1 и утвердил план КТ2. Первый PR КТ2 добавляет FastAPI и проверку доступности процесса. КТ2 PR 2 добавляет локальный стенд PostgreSQL с миграциями и техническое хранилище запусков. Решения DEC-01–07 сохраняют исходные статусы.

- [Базовая линия КТ1](docs/KT1_BASELINE.md) содержит состав, происхождение и статус материалов.
- [Требования](docs/02_REQUIREMENTS.md) и [сценарии S01–S06](docs/03_SCENARIOS.md) описывают поведение стенда.
- [Правила работы](AGENTS.md) описывают Git, ревью, аудит и AI-тестирование.

Для просмотра интерфейса откройте [prototype/index.html](prototype/index.html) в браузере. Прототип v0.2 работает как самостоятельная симуляция, без подключения к backend, БД и LLM.

## Запуск FastAPI

Для локального запуска установите uv 0.13.9 и выполните из корня репозитория:

```sh
cd backend
uv sync --locked --python 3.13.18
uv run --locked --python 3.13.18 python -m uvicorn app.main:app
```

Процесс слушает `127.0.0.1:8000`. Настройки `UVICORN_HOST`, `UVICORN_PORT` и `UVICORN_LOG_LEVEL` читаются из окружения процесса. Ответ `GET /health/live` — `200 {"status":"ok"}`.

Для сборки и запуска контейнера выполните из корня репозитория:

```sh
docker build -t ai-agents-qa-demo:local ./backend
docker run --rm -p 127.0.0.1:8000:8000 ai-agents-qa-demo:local
```

Для запуска тех же статических проверок и unit-тестов, что и в CI, выполните `docker build --target checks ./backend`. [Решения КТ2](docs/development/kt2-architecture.md).

## Локальный PostgreSQL и health

Перед запуском задайте независимые значения `QA_BOOTSTRAP_PASSWORD`, `QA_MIGRATE_PASSWORD` и `QA_API_PASSWORD` в окружении или в локальном игнорируемом `.env`. Используйте только отдельные тестовые учётные данные. Соберите образ и запустите стенд из корня репозитория.

```sh
docker compose build api
python scripts/start-local.py
```

По умолчанию HTTP доступен на `127.0.0.1:8000`. PostgreSQL доступна внутри сети Compose. `/health/live` проверяет HTTP-процесс. `/health/ready` и `/healthz` проверяют БД и ревизию. Обе проверки готовности возвращают 503 при отказе. Технические записи можно создавать только внутренним слоем хранения.

Обычная остановка `docker compose stop` сохраняет данные. Перед обновлением остановите API, проверьте резервную копию и соберите целевой образ. Во время обновления исключите параллельный запуск API и другого мигратора. Выполните `python scripts/start-local.py --update`. При ошибке миграции API останется остановленным. Пределы по умолчанию указаны в [Design](openspec/changes/kt2-postgres-run-store/design.md).

Предлагаемая структура по мере реализации:

| Путь | Назначение |
| --- | --- |
| `docs/` | Базовая линия и процедуры разработки |
| `prototype/` | Визуальный эталон КТ1 |
| `backend/` | FastAPI и симулятор API. Logistics Agent, QA Agent и QA Engine разделены внутри backend |
| `frontend/` | Интерфейс стенда |
| `tests/` | Автотесты и синтетические fixtures |
| `infra/` | Конфигурация окружений и инфраструктуры по мере необходимости |
