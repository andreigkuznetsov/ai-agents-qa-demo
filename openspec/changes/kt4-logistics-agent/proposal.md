# КТ4. Logistics Agent

Change-id: `kt4-logistics-agent`. [Issue №25](https://github.com/andreigkuznetsov/ai-agents-qa-demo/issues/25). Статус Requirements — ожидает утверждения.

## Why

КТ3 приняла шесть контрактов Logistics API Simulator. КТ4 проверяет, что агент выбирает инструменты, а сервер разрешает и ограничивает их исполнение. Приёмочный S01 требует наблюдения за реальной моделью и независимого подтверждения записи в БД.

## What Changes

- Добавить capability `logistics-agent` с требованиями к шести инструментам, серверному контексту, намерению, исполнению и восстановлению.
- Проверить S01–S06 со сценарным адаптером без платного LLM. Отдельно выполнить один операторский live S01 после утверждения провайдера, среды, модели и бюджетов.
- Сохранять безопасные события с корреляцией и все результаты live-попыток. Передавать в КТ5 интерфейс событий и идентификаторы, в КТ6 критерии сценарной регрессии и в КТ9 границы проверок отказов.

## Capabilities

### New Capabilities

- `logistics-agent` — последовательное серверное исполнение типизированных инструментов и проверяемый допуск live S01.

### Modified Capabilities

Нет. `postgres-runtime`, `run-store`, `compose-acceptance` и `logistics-api-simulator` остаются действующими.

| PR 1 | Типизированный HTTP-адаптер, серверный контекст, схемы, негативные проверки | Все шесть маршрутов соответствуют КТ3. Подмена контекста, лишние поля, неверные типы и недоверенный payload проходят негативные проверки. |

| PR 3 | Один утверждённый реальный провайдер, локальный CLI, preflight, один обязательный live S01 | При разрешённых условиях реальная модель проходит S01, отдельное чтение БД подтверждает ожидаемую запись. ## Approval and dependencies

До реализации действуют отдельные ворота Requirements, Design и Tasks. Этапы фиксируются в Issue №25. После утверждения всех трёх артефактов допускается отдельный planning baseline с `kind: planning`. Каждый из трёх продуктовых PR предоставляет фактические доказательства своего среза и проходит независимое ревью точного SHA. Системный аудит проводится по AGENTS.md. Sync/Archive допускается после приёмки всех срезов.

До начала PR 3 пользователь отдельно утверждает DEC-08, разрешённую среду и аккаунт, провайдера, версию модели и денежный и временной бюджеты. Допуск основан на фактическом preflight и предварительном разрешении серии. При отсутствии разрешённого доступа фиксируется BLOCKED_PRECONDITION, живое доказательство и приёмка КТ4 остаются открытыми. Варианты A/B приведены в [решениях КТ4](../../../docs/development/kt4-business-decisions.md).
