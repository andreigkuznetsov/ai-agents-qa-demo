# PostgreSQL runtime

## Purpose

Локальный стенд должен запускать API с ожидаемой ревизией PostgreSQL и позволять отличить работающий HTTP-процесс от готовности работать с базой.

## ADDED Requirements

### Requirement: AC-PG-001 Запуск API после миграции

Локальный стенд SHALL выполнять миграцию Alembic отдельным одноразовым сервисом Compose. API запускается только после успешного завершения миграции на готовой PostgreSQL. Старт ограничен конфигурируемым тайм-аутом. Ошибка миграции оставляет API незапущенным и видна оператору без раскрытия секретов. Ссылки: REQ-019, NFR-001, NFR-005.

#### Scenario: SC-PG-001 Чистый запуск

- **GIVEN** новый тестовый проект Compose с пустым томом PostgreSQL и корректной конфигурацией
- **WHEN** оператор запускает стенд
- **THEN** миграция завершается с кодом `0`, существует таблица `runs`, а ревизия БД совпадает с ожидаемой ревизией сборки
- **AND** API запускается после завершения миграции, а `/health/live`, `/health/ready` и `/healthz` возвращают `200` в пределах настроенного бюджета старта

#### Scenario: SC-PG-002 Ошибка миграции

- **GIVEN** изолированный тестовый проект Compose, в котором миграция управляемо завершается ошибкой
- **WHEN** оператор запускает стенд
- **THEN** сервис миграций завершается ненулевым кодом, API не запускается, а причина сбоя видна в состоянии сервиса или диагностике
- **AND** диагностика не содержит DSN или паролей

### Requirement: AC-PG-002 Повторная миграция

Повторный запуск миграции той же сборки на базе с ожидаемой ревизией SHALL завершаться успешно, сохраняя ревизию, схему и существующие записи. Ссылка: REQ-019.

#### Scenario: SC-PG-003 Повторная миграция с имеющейся записью

- **GIVEN** база на ожидаемой ревизии и синтетическая запись `runs` со всеми четырьмя полями
- **WHEN** повторно запускается миграция той же сборки
- **THEN** сервис завершает работу с кодом `0`, таблица и ожидаемая ревизия остаются на месте
- **AND** количество записей и четыре значения исходной записи совпадают с состоянием до запуска

### Requirement: AC-PG-003 Readiness зависит от БД и ревизии

`GET /health/ready` и `GET /healthz` SHALL возвращать одинаковый результат: `200` только при успешном запросе к настроенной PostgreSQL и ожидаемой ревизии схемы. При отказе, тайм-ауте или несовпадении ревизии оба маршрута возвращают `503` без внутренних подробностей. Тайм-аут конфигурируется. `GET /health/live` сохраняет `200 {"status":"ok"}` и работает без БД. Ссылки: REQ-019, NFR-002, NFR-005.

#### Scenario: SC-PG-004 БД недоступна после успешного запуска

- **GIVEN** работающие API и PostgreSQL с ожидаемой ревизией
- **WHEN** PostgreSQL останавливается, а процесс API продолжает работать
- **THEN** оба маршрута readiness возвращают `503` в пределах настроенного тайм-аута без DSN, пароля, SQL или stack trace
- **AND** `/health/live` продолжает возвращать `200 {"status":"ok"}`

#### Scenario: SC-PG-005 БД восстановилась

- **GIVEN** работающий API и отказ readiness после потери БД
- **WHEN** та же PostgreSQL с ожидаемой ревизией снова становится доступна
- **THEN** оба маршрута readiness возвращают `200` без перезапуска API

#### Scenario: SC-PG-006 БД доступна, ревизия не совпадает

- **GIVEN** работающий API, который может выполнить запрос к тестовой PostgreSQL
- **WHEN** чтение состояния схемы показывает несовпадающую или отсутствующую ревизию
- **THEN** оба маршрута readiness возвращают `503` без внутренней диагностики, а liveness остаётся `200`

#### Scenario: SC-PG-008 Истёк тайм-аут проверки БД

- **GIVEN** работающий API и тестовая PostgreSQL, проверка которой управляемо задержана дольше настроенного бюджета readiness
- **WHEN** поступают запросы к обоим маршрутам readiness
- **THEN** каждый запрос завершается ответом `503` по истечении бюджета с учётом согласованного допуска теста, без внутренних подробностей
- **AND** `/health/live` продолжает отвечать `200`

### Requirement: AC-PG-004 Сетевые границы стенда

Конфигурация Compose SHALL оставлять PostgreSQL доступной внутри сети стенда без публикации её порта на хост. HTTP API по умолчанию публикуется только на loopback-интерфейсе хоста. Учётные данные передаются конфигурацией окружения и не сохраняются в Git. Ссылки: REQ-019, NFR-001, NFR-002.

#### Scenario: SC-PG-007 PostgreSQL недоступна извне сети стенда

- **GIVEN** стенд запущен с конфигурацией Compose по умолчанию
- **WHEN** проверяются опубликованные порты и выполняется запрос к PostgreSQL со стороны сервиса внутри сети Compose
- **THEN** для контейнера PostgreSQL нет опубликованного порта на хосте, а запрос через внутреннюю сеть успешен
- **AND** опубликованный HTTP API доступен на loopback, но не привязан к wildcard или внешнему адресу хоста
