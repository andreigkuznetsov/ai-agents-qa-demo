# Техническое хранилище запусков

## Purpose

Техническое хранилище сохраняет минимальные метаданные тестовых запусков и позволяет проверить их адресацию по UUID и сохранность между запусками локального стенда.

## ADDED Requirements

### Requirement: AC-RUN-001 Минимальная запись с идентификатором запуска

Хранилище SHALL создавать и читать по `run_id` синтетические записи `runs` в общей PostgreSQL. Минимальная запись содержит ровно четыре поля: UUID `run_id` как первичный ключ, `schema_version` структуры записи, `created_at` с представлением в UTC и технический `status` со значением `CREATED`. В этом PR запись запуска не предоставляется через внешний API. Ссылки: REQ-009, REQ-019, NFR-002.

#### Scenario: SC-RUN-001 Две записи адресуются независимо

- **GIVEN** мигрированная тестовая PostgreSQL и два разных синтетических UUID
- **WHEN** слой хранения создаёт обе записи и читает каждую по своему `run_id`
- **THEN** каждое чтение возвращает только запись запрошенного UUID и все четыре её поля
- **AND** `schema_version` соответствует версии структуры, `created_at` читается в UTC, а статус каждой записи равен `CREATED`
- **AND** в схеме `runs` нет полей моделей, промптов, токенов, стоимости или результатов оценки

#### Scenario: SC-RUN-002 Первичный ключ исключает повтор UUID

- **GIVEN** синтетическая запись `runs` с известным UUID
- **WHEN** в PostgreSQL пытаются вставить ещё одну новую строку с тем же UUID
- **THEN** ограничение первичного ключа отклоняет вторую вставку, а число записей с этим UUID и значения исходной строки остаются прежними

### Requirement: AC-RUN-002 Сохранение при обычной остановке Compose

Технические записи SHALL сохраняться в томе PostgreSQL между обычной остановкой и повторным запуском того же проекта Compose. Обычная остановка не включает явное удаление тома. Ссылки: REQ-009, REQ-019, NFR-001.

#### Scenario: SC-RUN-003 Запись переживает остановку и запуск

- **GIVEN** успешно запущенный тестовый проект Compose и сохранённая синтетическая запись с известным `run_id`
- **WHEN** оператор останавливает стенд без удаления тома и запускает тот же проект с тем же томом
- **THEN** после готовности API слой хранения возвращает запись по исходному `run_id` с теми же четырьмя значениями
- **AND** повторный запуск не создаёт копию записи
