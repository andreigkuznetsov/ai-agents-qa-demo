## Критерии принятия КТ1
- Документы 01–07 существуют и согласованы между собой.
- S01–S06 сохранены по сути в соответствии с прототипом v0.2; изменения фиксируются явно.
- Для каждого сценария имеются initial state, user request, expected state, expected response, evaluator oracle и пример внедрённого дефекта.
- Неопределённые бизнес-правила и условия доступности live отмечены как открытые решения.
- Нет утверждения, что симулированные traces из HTML подтверждают работу AI/backend.

## Критерии отклонения КТ1
Необоснованное предположение о реальных логистических правилах, отсутствие одного из шести сценариев, смешение результатов QA Agent и QA Engine, отсутствие решения по изоляции данных либо скрытое включение внешних API/серверных расходов.

## Следующая задача после КТ1
Создать технический spike для КТ2: минимальная FastAPI + PostgreSQL + Docker Compose с health и структурированной записью запусков; не писать Agent Under Test до подтверждения архитектурных границ и схемы тестового состояния.
