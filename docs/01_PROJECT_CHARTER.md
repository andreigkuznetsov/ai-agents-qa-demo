# AI Agents QA Demo — паспорт проекта

**Версия:** 0.1-draft · **Контрольная точка:** КТ1 · **Статус:** на рассмотрении.  
**База:** принятый HTML-прототип v0.2 и согласованный пошаговый план разработки.  
**Язык документации:** русский. Идентификаторы, API и код — английский.

## Назначение
Работающий портфолио-стенд для проверки поведения AI-агента в процессе «перенос доставки через создание обращения». Тестируемый Logistics Agent взаимодействует с симулятором логистического API; независимый QA Engine проверяет наблюдаемые события и состояние данных; отдельный QA Agent (LLM-as-Judge) анализирует полноту и фактическую обоснованность ответа. Интерфейс показывает **обе трассы**, проверки QA Engine, сравнительную оценку и доказательства.

## Цели MVP v1.0
- Реальный Agent Under Test с вызовами инструментов, а не жёстко прописанный сценарный скрипт.
- Шесть сценариев **S01–S06** с начальным состоянием, тестовыми оракулами, позитивными и негативными вариантами.
- Управляемый логистический backend с PostgreSQL, сбросом состояния и отказами; не подключать производственные системы.
- Воспроизводимый replay и live-режим через конфигурируемый LLM API.
- Два независимых типа оценки: deterministic QA Engine и LLM QA Agent; отдельные вердикты с evidence.
- Локальный запуск через Docker Compose; публичное представление через GitHub Pages с записанными результатами, без обязательного VDS.
- Отчёты, трассы и измеримые метрики без выдуманных показателей эффективности.

## Аудитория
Работодатели и специалисты QA/AI engineering, изучающие портфолио; разработчик стенда, который запускает эксперименты и анализирует регрессии.

## В пределах MVP
S01–S06; логистический API-симулятор; test fixtures; агент выполнения; система оценки; replay/live; защищённый запуск; trace viewer; статический публичный отчёт; JSON-экспорт; CI без обязательных вызовов платных LLM.

## За пределами MVP
Самообучение; подключение к системам DPD; реальные персональные/производственные данные; собственный LLM-хостинг; RAG; мультиагентная бизнес-оркестрация; дорогая observability-платформа; общедоступные неограниченные платные LLM-запуски; интеграция с Analysis & QA Orchestrator (сохранить возможность будущего экспорта).

## Принятые решения
- Зафиксирован интерактивный UI-прототип v0.2 как **референс интерфейса**, без требования копировать внутреннюю JS-симуляцию.
- Две наблюдаемые трассы: Logistics Agent и QA Agent; независимый результат QA Engine.
- Все шесть сценариев обязательны. При реализации начинать с вертикального среза S01.
- Локальная разработка без аренды сервера; решение о постоянном публичном backend принимается отдельно.

## Ключевые риски
1. **Ложный PASS от LLM-оценщика.** Детерминированные инварианты имеют приоритет, LLM не может отменить их FAIL.
2. **Невоспроизводимость live LLM.** Версии моделей/промптов/fixtures фиксировать, replay хранить раздельно.
3. **Неподтверждённые бизнес-правила.** Запрещено трактовать учебные предположения как правила реальной логистики.
4. **Утечка секретов и затраты на LLM.** Секреты только на backend, лимиты/аутентификация для live.
5. **Переполнение VDS.** Тестировать потребление ресурсов до развёртывания; на MVP тяжёлые сервисы не добавлять.

## Этапы и критерии перехода
