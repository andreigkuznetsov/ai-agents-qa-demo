# Независимое ревью PR

1. Укажи в описании PR границы задачи, критерии приёмки, затронутые требования, выполненные проверки и срок аудита по [процедуре](audit-process.md).
2. Свяжи PR с Issue и подтверди связь в секции Development. Если GitHub автоматически закрывает привязанную Issue при merge, перед слиянием получи также разрешение на закрытие. После разрешённого merge проверь связь и статус Issue.
3. Передай задачу, требования, полный head SHA, базовый SHA и ссылки на доказательства отдельной сессии Codex или отдельному субагенту. По возможности передавай контекст без переписки автора. Ревьюер самостоятельно изучает diff и проверяет указанный SHA. Автор сохраняет проверяемое состояние до завершения ревью.
4. Сохрани проверенный SHA, идентификатор или ссылку на сессию (при наличии), охват, замечания, результаты, ограничения и ссылку на отчёт. Различай проверки автора и ревьюера. После исправлений передай новый SHA и итоговый diff на повторное ревью.
5. Перед merge сверь head с проверенным SHA и повторно проверь срок аудита.

Самопроверка не заменяет независимое ревью. При недоступности субагента используй отдельную сессию Codex.
