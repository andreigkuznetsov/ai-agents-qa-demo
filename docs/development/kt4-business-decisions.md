# КТ4. Решения по Logistics Agent

Редакция 1 от 24.11.2026. Решения пользователя получены в Codex. Requirements на согласовании. [Журнал Issue №25](https://github.com/andreigkuznetsov/ai-agents-qa-demo/issues/25)

| Решение | Статус | Правило |
| --- | --- | --- |
| Архитектурное направление | Утверждено | Собственный последовательный Python executor, сменный LLM-адаптер, шесть типизированных инструментов, серверная политика. Один change-id, три продуктовых PR. |
| DEC-08 | Открыто | Anthropic API, OpenAI API, OpenRouter и Ollama остаются кандидатами. Нужны подтверждённый доступ, допустимая среда и условия использования, проверка tool calling, согласованные провайдер и версия модели. Обход территориальных ограничений запрещён. При отсутствии разрешённого варианта live получает BLOCKED_PRECONDITION. |
| DEC-09 | Утверждено для КТ4 | Каждая live-попытка получает отдельный синтетический run_id. Операция принадлежит серверу. Разрешение на POST долговечно расходуется до отправки. После сбоя или рестарта автоматическая запись исключена. Маркер расходования не доказывает отправку или фиксацию. |
| DEC-10 | Утверждено для КТ4 | Допуск только через локальный CLI доверенного оператора. Публичный API управления агентом вне КТ4. |
| Намерение и дата | Утверждено | Информационный запрос не разрешает POST. Явная просьба с конкретным заказом и однозначной допустимой датой достаточна. Для даты без года нужен доверенный reference_year и единственное совпадение. Относительные и неоднозначные даты уточняются. Системное время не определяет бизнес-дату. |
| Пределы количества вызовов | Утверждено | Максимум 6 обращений к модели и 6 попыток инструментов на операцию, максимум 1 POST и 1 сверка. |
| Денежный и временной бюджеты | Открыто | A/B ниже служат вариантами для согласования. PR 3 требует отдельного решения о бюджете и условиях запуска. |
| DEC-11 и DEC-12 | Последующие этапы | Пороги оценки и публикация не входят в согласование КТ4. |

### Варианты бюджета live

| Вариант | Денежный предел | Общий дедлайн после готовности стенда | Дедлайн запроса модели | Резерв на сверку и завершение |
| --- | --- | --- | --- | --- |
| A, одна приёмочная попытка | $0,05 на попытку и серию | 60 с | до 8 с | 8 с |
| B, до трёх отдельно разрешённых попыток | $0,05 на попытку, $0,15 на серию | 120 с на попытку | до 15 с | 10 с |

PR 3 предусматривает один обязательный фактический S01. Дополнительные попытки варианта B требуют отдельного разрешения, предельного числа и правила остановки до начала серии. Все попытки фиксируются отдельно. Числа A/B не являются рабочими значениями по умолчанию. Дедлайн ограничивает ожидание клиента и сам по себе не подтверждает прекращение тарификации у провайдера.

Исторические формулировки сохраняются в [реестре КТ1](../07_DECISIONS.md). [Решения КТ3](kt3-business-decisions.md) и её действующий API-контракт применяются без изменений. Ограничение DEC-10 закрывает операторский допуск КТ4. Полный критерий защищённого серверного API из REQ-017 остаётся за пределами КТ4.
